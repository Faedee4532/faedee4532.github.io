Nexus — Easy/Linux Writeup

Executive Summary. An Easy-difficulty Ubuntu 24.04 box masquerading as a corporate energy utility. The chain opens with a vhost hunt that exposes a self-hosted Gitea instance, whose public repository history leaks a plaintext DB password. That key unlocks a Krayin CRM authenticated file-upload RCE (CVE-2026-38526), and a credential-reuse habit turns the web-tier shell into a live SSH user. Root falls through a root-run Gitea "template sync" systemd timer and an unsanitized os.path.join(), where a git mktree/commit-tree traversal rewrites the porcelain path rules to drop a key into /root/.ssh/authorized_keys.

Phase 01 — Reconnaissance

An aggressive nmap -A -Pn scan surfaces only two doors: port 22 (OpenSSH 9.6p1) and port 80 (nginx 1.24.0), which redirects to nexus.htb. The redirect is the first tell — name-based hosting means more than one site lives on the IP. A subdomain/vhost fuzz (ffuf) against nexus.htb splits the host into two vhosts: git.nexus.htb (a Gitea instance) and billing.nexus.htb (the Krayin CRM).

  • The corporate landing page ("Nexus Energy Authority") leaks an internal contact on a careers posting: j.matthew@nexus.htb — a usable username later.
  • git.nexus.htb runs Gitea 1.26.0 with require_signin=False, so every public repo is browsable without an account.

Phase 02 — Initial Access

Under the Gitea admin account a public repo, admin/krayin-docker-setup, holds the Docker Compose for the billing CRM. Browsing its commit history reveals the .env file committed in plaintext and later redacted — the old DB password survived in the diff: N27xh!!2ucY04. Combined with the leaked email, that is a valid CRM credential pair.

Login succeeds against billing.nexus.htb/admin. The dashboard reports Krayin CRM 2.2.0. A version check points to CVE-2026-38526 — an authenticated, unrestricted file-upload RCE in the TinyMCE media endpoint (/admin/tinymce/upload), CVSS 9.9 Critical, with a public PoC on Exploit-DB (52629).

  • Upload a pentestmonkey PHP reverse shell by renaming shell.php through the multipart form and forwarding it in Burp.
  • The response reveals the stored location, e.g. /storage/tinymce/<hash>.php; curl it to catch a www-data shell on a listener.
  • Upgrade to a PTY (python3 -c 'import pty;pty.spawn("/bin/bash")').

Phase 03 — User Access

As www-data, read the live app config directly: cat .env exposes a fresh DB password (y27xb3ha!!74GbR) — rotated from the git leak but still the same reuse pattern. Enumerating /etc/passwd shows jones with a login shell. A credential-reuse login (ssh jones@nexus.htb) with the DB password lands a stable shell, and user.txt is read.

Root then falls through the Gitea template-sync mechanism. Two paths were documented:

  • Automated. A bash script chains the Gitea API token grab, template repo creation, tree construction, and push in one run.
  • Manual plumbing. The precise, room-tied trick. The template-sync script reads git ls-tree -r HEAD of any template=true repo and joins each filepath with os.path.join(stage_path, filepath) without sanitizing it.

Git's porcelain layer refuses paths containing / or empty components, so a raw absolute path can't be committed normally. The solution builds ../../../../../root/.ssh/authorized_keys through five nested mktree tree objects, then commits and pushes with commit-tree/update-ref so the timer picks the crafted path up within a minute and writes the attacker's SSH key as root.

Findings & CVEs

  • 9.9 · Critical CVE-2026-38526 — Krayin CRM TinyMCE unrestricted file-upload RCE (CVSS 9.9, Critical). Authenticated PHP upload → www-data.
  • Git history cred leak — .env committed plaintext in a public Gitea repo.
  • Credential reuse — DB password reused for jones SSH.
  • os.path.join() traversal — unsanitized filepath in a root-run systemd timer, escalated with git mktree/commit-tree plumbing.
