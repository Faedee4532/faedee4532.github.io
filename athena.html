Athena — Linux Writeup

Executive Summary. A THM box (hostname ROUTERPANEL) exposing SSH, an Apache site, and Samba. A small "ping" utility at /myrouterpanel has an OS command injection that only accepts a newline (%0a) when the usual operators are blocked. A root cron job running backup.sh as the athena user is pinned down with pspy64, giving the user. Root falls through an insmod sudo shortcut to a custom LKM rootkit whose real signal number is 57, not the documented 64.

Phase 01 — Reconnaissance

nmap -sV -sC -A opens ports 22 (SSH), 80 (Apache 2.4.41), 139/445 (Samba 4.6.2). The Apache site is a thin landing page. Samba allows an anonymous/null-session login; the public share holds msg_for_administrator.txt, which points to a new in-development ping system at /myrouterpanel.

The ping form accepts an IP; ;, |, and & are filtered with an "Attempt hacking" response — but a URL-encoded newline (%0a) slips past and runs a follow-on command, confirming injectability.

Phase 02 — Initial Access

Capture the ping POST in Burp and feed it to commix, which confirms the ip parameter is injectable via the classic results-based technique. Request a pseudo-TTY shell and drop a reverse shell (netcat) as www-data.

  • Simple test: ip = 10.9.2.147%0aid
  • Reverse-shell payload (URL-encoded): download a shell, chmod +x, then execute it via the injected newline.

Phase 03 — User Access

Upload and run pspy64 to watch processes in real time. It reveals user athena (UID 1001) running /bin/bash /usr/share/backup/backup.sh on a schedule (athena_backup.service). Read the script: it backs up /home/athena/notes/ with zip and is owned www-data:athena, so www-data can overwrite it.

Inject a reverse shell into backup.sh; within one cron run the user shell connects and user.txt is read.

Phase 04 — Privilege Escalation

sudo -l shows athena may run, unattended, the root /usr/sbin/insmod /mnt/.../secret/venom.ko. The module is a custom LKM rootkit (author m0nad) — the same lineage as Diamorphine. The README claims signal 64 makes any process root, but that's a decoy.

Run modinfo, then decompile venom.ko in Ghidra and follow hacked_Kill: the success condition is rax == 0x39, i.e. decimal 57. The author hand-edited the module so the real trigger is kill -57 <pid> on any process — that fires the hidden syscall handler and grants root.

  • Documented (wrong): kill -64 6666
  • Correct (reverse-engineered): kill -57 6666 → root

Findings & CVEs

  • OS Command Injection — %0a newline bypass around a small operator blocklist.
  • Writable cron script — backup.sh owned by athena's group, run by the user.
  • LKM rootkit (venom.ko) — insmod sudo shortcut; correct trigger signal reverse-engineered to 57.
